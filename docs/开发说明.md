# 开发说明

面向想改行为、换数据或排查问题的人。读完应该能回答三个问题：页面是怎么把一篇 Markdown 变成带标注的正文的，状态存在哪里，词典服务在做什么。

---

## 1. 技术栈与约束

- 纯静态：原生 HTML + CSS + JavaScript（IIFE，无框架、无模块打包、无构建步骤）。
- 运行方式：`file://` 直接打开即可；可选 `node server.mjs` 提供本地词典查询。
- 运行环境：现代浏览器（需要 `IntersectionObserver`，缺失时退化为一次性全量标注）；词典服务建议 **Node 20.12+**（用到 `fs.readdirSync` 的递归选项与 `Dirent.parentPath`），开发时使用的是 Node 24。
- 第三方库全部入库在 `vendor/`，**不要**用 `npm install` 覆盖：`server.mjs` 直接按相对路径导入 `vendor/jsdict/node_modules/js-mdict`。

页面加载顺序固定在 `index.html` 末尾：

```text
markdown-it.min.js → katex.min.js → markdown-it-katex.js
→ data/frequency.js → data/glossary.js → data/phrases.js
→ sample.js → app.js
```

`data/*.js` 只是给 `window` 挂全局对象，`app.js` 依赖它们已经就绪。

## 2. 渲染与标注管线

一篇文稿从文件到屏幕，经过这几步：

### 2.1 载入

`handleFile` → `loadDocument(rawText, fileName, modifiedAt)`：

1. 去掉 BOM，写入 `state.markdown` / `state.fileName` / `state.modifiedAt`；
2. 计算 `state.documentKey = fnv1a(正文) + ":" + 文件名小写`，用于区分文稿的进度、书签和高亮；
3. 调用 `saveLastDocument()`（正文超过 1.5 MB 时跳过）；
4. 调用 `renderDocument()`。

### 2.2 Markdown → DOM

`renderDocument()` 里：

```js
elements.content.innerHTML = markdown.render(state.markdown);
```

markdown-it 配置为 `html: true, linkify: true, typographer: true, breaks: false`。开启 `html: true` 是为了支持 `<sup>`、`<span>` 等排版标签，因此随后必须过一遍 `sanitizeHtmlFragment`（见第 6 节）。

之后：

- 所有 `http(s)` 外链补 `target="_blank"` 与 `rel="noopener noreferrer"`；
- `buildTableOfContents()` 生成目录：有标题用标题，没有则用 `inferGeneratedOutline` 按章节标记、分隔线、段落结构推断，并给目标块分配 `auto-section-N` 的 id；
- 每个正文顶层子节点写入 `dataset.readingIndex` 和 `dataset.annotationState = "pending"`，原始 `innerHTML` 存入 `blockSources`（WeakMap），供之后重排时还原；
- 恢复已保存的高亮。

### 2.3 懒标注

```js
state.annotationObserver = new IntersectionObserver(
  (entries) => entries.forEach((entry) => entry.isIntersecting && annotateBlock(entry.target)),
  { root: null, rootMargin: "600px 0px", threshold: 0 }
);
```

也就是说，只有进入视口上下 600px 的**顶层块**才会被处理。`annotateBlock(block)` 的流程：

1. `collectTextNodes(block)` 用 `TreeWalker` 收集纯文本节点，跳过 `a`、`code`、`pre`、`button`、`label`、`input`、`textarea`、`select`，以及已标注节点、`.katex`、`.math-inline`、`.math-block`；
2. `findMatches(text)` 在单个文本节点内做匹配（不跨节点）：
   - 先用 `/[A-Za-z]+(?:['’][A-Za-z]+)*/g` 切词；
   - 若「优先识别词组」开启，从最长 5 词往 2 词回溯，命中 `window.MD_PHRASES` 且 `shouldAnnotatePhrase` 为真就整体标注，并跳过被覆盖的词；
   - 否则逐词查 `getWordInfo`，满足 `shouldAnnotateWord` 就标注；
3. `buildGloss()` 生成节点，替换原文本节点。

### 2.4 什么词会被标注

```js
function shouldAnnotateWord(rawWord, info) {
  if (!state.prefs.frequency) return false;
  if (!info || isKnown(rawWord)) return false;
  if (isForcedWord(rawWord)) return true;        // 生词表优先
  if (state.prefs.mode === "all") return true;
  return info.rank > state.prefs.cutoff;          // 难词优先
}
```

词组同理，`phraseRank` 取组内各词排名的最大值，再与 `cutoff` 比较。词组命中要求组内每个词都不是已掌握词。

### 2.5 词形还原

`wordVariants(rawWord)` 是规则式还原，覆盖：

- 所有格 `'s` 去掉；
- `-ies` → `-y`；
- `-es` → 去 `e` / 去 `es`；
- `-s` → 去 `s`；
- `-ing` → 去词尾、补 `e`、去重复辅音；
- `-ed` → 同上；
- `-ly` → 去 `ly`。

`getWordInfo` 在变体里取最小排名与第一个命中的释义，因此 `becomes` 会按 `become` 的条目处理，释义也记在原形键上。**不规则变化不在规则里**（`went`、`children`），只能靠词表直接收录。

### 2.6 参数变化时只重排附近

调整阈值、模式、词组开关或词表时调用 `scheduleRefresh()`（60ms 防抖）→ `refreshAnnotatedBlocks()`：

1. 先用 `captureReadingAnchor()` 记下当前阅读位置；
2. 对每个已标注块恢复 `blockSources` 里的原始 HTML；
3. 只重新标注当前视口上下 700px 内的块，其余回到 `pending`；
4. 用锚点 `restoreLocation()` 把滚动位置拉回原处。

因此侧栏「当前阅读」的统计是**已标注范围**的统计，不是全文统计。

## 3. 数据结构

### 3.1 内置数据（`data/*.js`）

```js
// frequency.js
window.MD_FREQUENCY = { "word": [rank, zipf], ... };

// glossary.js
window.MD_GLOSSARY = { "word": ["释义1", "释义2"], ... };

// phrases.js（键是空格连接的小写词组，最长 5 词）
window.MD_PHRASES = { "machine learning": ["机器学习"], ... };
```

`rank` 是 wordfreq 排名，越小越常见；`zipf` 目前只用于数据说明，不参与标注判断。`metadata.json` 记录数据规模与词典版本，供「数据说明」对话框展示。

### 3.2 运行时状态

`state` 里与持久化相关的部分：

| 字段 | 含义 |
| --- | --- |
| `prefs` | 阈值、模式、字号、栏宽、主题、词组开关、词典勾选 |
| `knownWords` / `forcedWords` | 掌握词表 / 生词表（Set） |
| `glossOverrides` | 手动选定的词典释义，键为词条原形 |
| `progressMap` | `documentKey → 位置锚点` |
| `bookmarkMap` | `documentKey → 书签数组` |
| `highlightMap` | `documentKey → 高亮数组` |
| `documentKey` | 当前文稿标识 |

### 3.3 本地存储键

```js
const STORAGE = {
  prefs: "reading-room:prefs:v1",
  known: "reading-room:known:v1",
  forced: "reading-room:forced:v1",
  glosses: "reading-room:glosses:v1",
  document: "reading-room:last-document:v1",
  progress: "reading-room:progress:v2",
  bookmarks: "reading-room:bookmarks:v3",
  legacyBookmarks: "reading-room:bookmarks:v2",
  highlights: "reading-room:highlights:v1",
};
```

所有读写都包在 `try/catch` 里，存储被禁用或超额时降级为「本次会话可用、刷新后丢失」，不会中断阅读。

### 3.4 位置锚点

`captureReadingAnchor()` 以视口 32% 高度处为「阅读线」，取该线所在的块：

```js
{ blockIndex, offsetRatio, excerpt, scrollRatio, chapter, chapterId, fileName, createdAt, updatedAt }
```

恢复时 `findAnchorBlock()` 先按 `blockIndex + excerpt` 精确匹配，失败再按 `excerpt` 全文查找，最后按 `excerpt` 前 48 字符模糊匹配——这样即使重排或增删段落，也能大致回到原处。

### 3.5 书签与高亮

- 书签：`{ id, ..., anchor }`，`anchor` 即上面的位置锚点；列表里显示章节标题或摘录。
- 高亮：`{ id, text(≤600), startBlockIndex, startOffset, endBlockIndex, endOffset, createdAt }`。偏移是「块内纯文本字符偏移」，`applySavedHighlights()` 在渲染后、标注前重放，并把带 `<mark data-highlight-id>` 的结果存进 `blockSources`。`collectTextNodes` 不跳过 `mark`，所以高亮范围内照样生成标注，两者叠加显示；重排时从 `blockSources` 还原，高亮不会丢失。

## 4. 本地词典服务（`server.mjs`）

### 4.1 启动

```bash
node server.mjs [port]      # 默认 8765，被占用时最多向后尝试 20 次
```

只绑定 `127.0.0.1`。启动成功后写入 `.local-server.json`（`{ port, pid }`），该文件被 `.gitignore` 忽略。

`start.sh` 的职责：

1. 探测目标端口是否已有健康服务（`/api/health`），没有就 `setsid nohup` 拉起；
2. 最多等 20 秒；
3. 用 `file://` 打开 `index.html`（刻意不用 HTTP，见 4.5）；
4. `--stop` 时按 `node <路径>/server.mjs <port>` 的模式 `pkill`。

### 4.2 词典发现

`loadConfig()` 合并两个来源并去重：

1. `dictionaries.json` 的 `roots`；
2. GoldenDict 配置 `~/.config/goldendict/config` 中所有 `<path>` 目录。

`dictionaries.json` 不存在且配置里没有 `roots` 字段时，会自动写出当前结果。

`scanDictionaries()` 递归（`readdirSync({ recursive: true })`）收集 `.mdx`，用文件名推断方向（`directionLabel`：`bilingual` / `en-en` / `collocation` / `roots` / `medical` / `ja` / `other`），再按方向优先级和名称排序。词典 id 直接用绝对路径。

### 4.3 查词

`lookupInDictionary(id, word)`：

1. 用 `wordVariants`（服务端自己的一份，规则与前端接近）逐个变体尝试 `mdx.lookup`；
2. `@@@LINK=` 重定向最多跟随 3 层；
3. `extractSenses` 把词条 HTML 转文本、按行过滤噪音（`SENSE_NOISE`），生成义项；
4. `splitSenseParts` 用中文字符/标点判断，把中英混排的义项拆成 `EN` 与 `中` 两段；
5. `sanitizeArticle` 供「展开完整词条」使用，单条上限 `MAX_ARTICLE_CHARS = 60000`。

已打开的 MDX 用 Map 做 LRU，最多同时打开 `MAX_OPEN_DICTIONARIES = 5` 部。

### 4.4 接口

| 方法 | 路径 | 参数 | 返回 |
| --- | --- | --- | --- |
| GET | `/api/health` | — | `{ ok, dictionaries, roots }` |
| GET | `/api/dictionaries` | — | `{ ok, roots, dictionaries[] }`，每项含 `id/name/detail/direction/size` |
| GET | `/api/lookup` | `word`，可重复 `dict` | `{ ok, word, elapsed, results[] }` |
| POST | `/api/open-goldendict` | JSON `{ word }` | `{ ok }`，`spawn("goldendict", [word])` |
| GET | 其他路径 | — | 静态文件，路径必须落在项目根目录内 |

静态服务用 `path.resolve` + `startsWith(ROOT)` 做目录穿越防护，并带一份 MIME 映射。

### 4.5 为什么页面用 `file://`

`file://` 与 `http://127.0.0.1` 在浏览器里是**两个不同的源**，`localStorage` 不共享。`start.sh` 固定用 `file://` 打开，让词表、进度、书签始终落在同一份存储里；页面在 `file://` 下没有同源 API，于是逐个探测 8765–8770 端口找服务（`resolveApiBase`）。

需要注意的一处不一致：服务在端口被占用时最多能漂到 8785，而前端只探测到 8770。若落在 8771 以上，页面会显示「未连接」。约定用 `--port` 把起始端口压在 8770 以内即可。

## 6. 安全模型

- **HTML 清洗**：`markdown-it` 开启 `html: true`，因此渲染结果必须经过 `sanitizeHtmlFragment`：
  - 标签白名单 `SAFE_HTML_TAGS`（`sup`、`sub`、`span`、`mark`、`kbd`、`abbr` 等）；
  - 标签黑名单 `UNSAFE_HTML_TAGS`（`script`、`iframe`、`style`、`svg`、`img`、`form`、`math` 等）；
  - 属性白名单 `SAFE_HTML_ATTRIBUTES`，`style` 走 `safeHtmlStyle`、颜色走 `safeHtmlColor` 过滤；
  - 兼容中文弯引号书写的属性。
- **外链隔离**：http(s) 链接统一 `target="_blank" rel="noopener noreferrer"`。
- **标注节点用 DOM API 构建**（`createElement` + `textContent`），不拼接 HTML 字符串。
- **本地服务**：只监听回环地址；静态服务做根目录前缀校验；查词入参截断到 120 字符；`open-goldendict` 用参数数组 `spawn`，不经过 shell。
- **网络**：页面除 `127.0.0.1` 外不发起请求。

## 7. 常见改动怎么做

### 换掉词频或释义数据

1. 生成新的 `data/frequency.js`、`glossary.js`、`phrases.js`，保持 `window.MD_*` 的对象结构；
2. 同步更新 `data/metadata.json` 与 `NOTICE.txt`；
3. 硬刷新页面（脚本无版本号，浏览器可能缓存）。

注意：释义数据若派生自 CC-CEDICT，必须继续以 CC BY-SA 4.0 发布。

### 改默认阈值 / 默认模式

`DEFAULT_PREFS`（`app.js` 约 90 行）。老用户的偏好已存进 `localStorage`，改默认值只影响新用户；测试时先清掉 `reading-room:prefs:v1`。

### 改标注密度或颜色分档

- 判定逻辑：`shouldAnnotateWord` / `shouldAnnotatePhrase`；
- 颜色分档：`frequencyBand`（≤5000 中频、≤15000 低频、其余罕见）；
- 样式：`app.css` 中的 `.annotated-word.band-*` 与 `.gloss`。

### 改主题

`app.css` 顶部 `:root` 与 `[data-theme="dark"]` 两套 CSS 变量（`--paper`、`--ink`、`--reader-bg`、`--vermilion` 等）。字号与栏宽由 JS 写入 `--reader-font-size`、`--reader-width`。

### 加一个快捷键

`handleKeyboard` 里加分支，注意开头会过滤输入框内与带修饰键的按键；同时更新 `index.html` 底部的快捷键提示与 README。

### 支持更多 HTML 标签

改 `SAFE_HTML_TAGS` 与 `SAFE_HTML_ATTRIBUTES`，但不要放行 `script`、`iframe`、`style`、事件属性。

## 8. 调试

```bash
# 服务是否在跑
curl -s http://127.0.0.1:8765/api/health | jq

# 已发现哪些词典
curl -s http://127.0.0.1:8765/api/dictionaries | jq '.dictionaries[].name'

# 查一个词（dict 用绝对路径，可重复）
curl -sG http://127.0.0.1:8765/api/lookup \
  --data-urlencode 'word=nuance' \
  --data-urlencode 'dict=/path/to/a.mdx' | jq
```

- 服务日志：`.server.log`（`start.sh` 重定向）或启动终端输出。
- 前端：控制台可直接看 `window.MD_FREQUENCY["word"]`、`localStorage` 里的 `reading-room:*`。
- 某词没被标注时，依次确认：`getWordInfo(word)` 是否有返回、`isKnown`、`isForcedWord`、`prefs.mode` 与 `prefs.cutoff`。
- 词典按钮不出现：`state.dictionaryReady` 是否为真、`prefs.dictionaries` 是否非空。

## 10. 已知技术债

- `app.js` 约 3000 行、单个 IIFE，状态与 DOM 直接耦合，没有模块边界。
- 依赖 `window` 全局数据与浏览器存储，无可注入的存储层，难以写单测。
- 词形还原是规则匹配，不规则动词、名词只能靠词表命中。
- `localStorage` 配额有限（典型 5 MB/源），文稿持久化阈值定在 1.5 MB。
- `file://` 与 `http://` 双源导致的存储分裂，是 `start.sh` 与前端端口探测共同造成的既定设计。
- 服务端端口漂移上限（8785）大于前端探测上限（8770），属于历史遗留不一致。
- 无版本号 / 缓存戳，更新后可能需要强制刷新。
